# 出品フォト v1.0

出品写真を2〜5枚まとめて選び、1画面で結合・調整・保存するスマホ向けPWAです。React + TypeScript + Vite。広告・ログイン・外部DB・写真のアップロードはありません。

このバージョンは `feat/shuppin-photo-v1-rebuild` で新規設計しています。mainへのマージと公開は、実機での動作確認後に行ってください。

## 使い方

1. 大きな「写真を選ぶ」から2〜5枚を一度に選択します。追加の確定操作なしで自動配置します。写真選択画面の選択順ではなく、ブラウザが返すFileListの順番を維持します。
2. レイアウトをタップして配置を変更します。2枚は上下、3枚は上1＋下2、4枚は2×2、5枚は上2＋下3が初期配置です。
3. 写真をタップして選択し、1本指で移動、2本指で拡大縮小・回転・移動を同時に操作します。「調整」で倍率、−180°〜180°の角度、90°回転、リセットを使えます。
4. 「入れ替え」を押して移動先の写真・番号をタップします。写真に付随する変形も移動します。「差し替え」「削除」、空き枠への追加もできます。
5. 「余白」で白・黒・グレー、外側余白、枠間の隙間、角丸を変更します。
6. 右上の「保存」を押します。対応するiPhoneでは共有画面の「画像を保存」を選びます。非対応・失敗・キャンセル時も完成画像を保持します。長押し保存、JPEGダウンロード、共有の再試行が可能です。

写真をまとめて選び直すとき、新規作成するときは確認を表示します。選び直しのキャンセルや画像読込失敗では現在の編集を保持します。保存には全枠の写真が必要です。

## 開発

Node.js 22.12以降（推奨22 LTS）、npmを使用します。

```sh
npm ci
npm run dev
# http://localhost:5173/shuppin-photo/
npm run typecheck
npm test
npm run build
npm run preview
```

ブラウザテスト:

```sh
npx playwright install --with-deps chromium
npm run build
npm run test:e2e
```

`/usr/bin/chromium` があれば使用し、なければPlaywright付属Chromiumを使用します。任意の実行ファイルは `CHROMIUM_PATH` で指定できます。

## 実装

- `src/model.ts`: 全12レイアウト、正規化した領域、写真単位の変形、2点間ジェスチャーと中点アンカー。
- `src/EditorCanvas.tsx`: Pointer Events、ポインタキャプチャ、指の増減時の基準変更、選択と空き枠タップ。
- `src/photos.ts`: ネイティブ画像デコード、EXIFの向き、長辺2400pxへの縮小、オブジェクトURLと画像メモリの解放。
- `src/render.ts`: 表示と出力で共通のクリップ・移動・回転・拡大描画。2000×2000 JPEG、品質0.95。
- `src/App.tsx`: 編集UI、ファイル選択、写真管理、確認、保存用JPEGの事前生成・共有・代替保存。
- `scripts/sw.mjs`: ビルド済みの実ファイルからハッシュ付きオフラインシェルを生成。

写真の座標はキャンバスに対する相対値です。移動は枠内に制限せず、はみ出した部分のみ切り抜きます。縮小すると全体を表示でき、空いた部分は背景色になります。レイアウト変更・入れ替えでも写真単位の位置・倍率・角度を保持します。余白のpxは360px幅のキャンバス相当で、出力サイズへ比例換算します。

JPEGは操作終了から180ms後に事前生成します。操作中は生成せず、古い編集状態のJPEGを保存できないよう、準備済みリビジョンを照合します。ユーザーの保存クリック中に `navigator.share({ files })` を呼び、非同期エンコードを先に挟みません。写真アプリへの無確認の直接書き込みはブラウザではできません。

写真は順次読み込み、長辺2400pxのCanvasに保持します。解放時にCanvas寸法を縮めます。最大60MB/枚。元画像のデコード時には一時的に元解像度のメモリが必要で、極端に大きい写真やメモリの少ない端末には限界があります。色補正・美化は行いませんが、JPEG再圧縮とブラウザの色変換は発生します。

## PWAとGitHub Pages

- `vite.config.ts` のbaseは `/shuppin-photo/`。manifestのstart_url・scope・アイコンは相対パスです。
- HTTPSのGitHub Pagesで動作し、Safariの共有メニューから「ホーム画面に追加」できます。
- 最初のオンライン読込とService Workerのインストールが完了すると、アプリをオフライン起動・編集・JPEG出力できます。端末の写真はキャッシュへ保存しません。
- ビルド内容とSW生成コードのハッシュでキャッシュを更新します。新SWは編集中のページを強制再読込せず、旧ページをすべて閉じて次回開いたときに適用します。アプリを再度開いても古い場合はSafariとホーム画面PWAの両方を閉じ、オンラインで再起動してください。
- `.github/workflows/ci.yml` はPR/開発ブランチで型・単体・ビルド・ブラウザ検証を実施し、公開しません。
- `.github/workflows/pages.yml` はmainだけをデプロイします。開発ブランチからの手動起動でも公開ジョブは実行されません。
- リポジトリの **Settings → Pages → Source: GitHub Actions** を使用します。既存設定は今回変更していません。PRのマージ前に公開版は置き換わりません。

## 制約・確認事項

- iPhone Safari、ホーム画面PWA、Android Chromeの実機操作は未検証です。実際の共有シート、写真アプリ保存、ホーム画面追加、ノッチ、写真ライブラリのHEIC変換、低メモリ動作は実機で確認が必要です。
- JPEG/PNGなどブラウザがデコードできる形式に対応します。HEIC/HEIFはOS・ブラウザ依存で、非対応の場合はJPEG/PNGへの変更を案内します。外部変換サービスは使用しません。
- 編集内容はメモリ内のみで、再読込・アプリ終了・OSによる破棄で消えます。利用可能なブラウザでは離脱確認を表示しますが、iOSのアプリ強制終了は防げません。
- 出力JPEGは単一の静止画です。Live Photosやアニメーション、HDRの保持は対象外です。
- Safari側のストレージ削除・容量不足・プライベートモードなどによりオフラインキャッシュが利用できない場合があります。
- 通常の縦向きは画面内に収まるUIです。高さ480px以下の横向き等は操作領域を確保するためページスクロールを許可します。
