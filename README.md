# 出品フォト

スマホで2〜5枚の商品写真を正方形の1枚に結合する、React + TypeScript + Viteの静的PWAです。広告・会員登録・バックエンドはありません。写真はブラウザ内のCanvasで処理し、アップロードや解析用の外部通信は行いません。フォントも端末のものを使用します。

## 開発

Node.js 22以上を推奨（この環境では24で検証）。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run preview
```

既存のチェックアウトを使用できます。追加のworktreeは不要です。

## 操作

1. 中央の空き枠をタップし、その枠に写真を1枚追加します。「＋ まとめて」なら複数枚を選べます。まとめて追加した枚数に合わせて枠数とレイアウト候補が増えます。
2. 下部の「2枚〜5枚」で枠数を選び、「レイアウト」の横スクロール一覧から配置をタップします。枚数を減らしても枠の外の写真は保持し、枚数を戻すと再表示します。
3. 写真は直接ドラッグ・2本指で拡大縮小できます。写真をタップして選択し、編集エリア下の「写真を差し替え」を押すと、その枠だけ変更できます。ドラッグ・ピンチでは写真選択を開きません。
4. 「枠線・余白」で背景色・余白・角丸、「調整」で写真選択・倍率・リセット・並び替え・削除を操作します。
5. すべての表示枠に写真が入ると保存できます。「準備中…」が終わったら右上の「保存」を押します。対応ブラウザではこのタップから直接共有画面を開きます。
6. iPhoneの共有画面に「画像を保存」があれば選択します。見つからない場合や共有非対応の場合は、完成画像を長押しして保存、またはJPEGをダウンロードしてください。共有をキャンセル・失敗した場合も完成画像を残すので、「もう一度共有する」で再操作できます。

出力は2000×2000px・JPEG（品質0.95）。写真は枠を埋めるように中央で切り抜かれます。色補正・美肌・ロゴ除去などの自動加工は行いません。ただしCanvas/JPEG変換による再圧縮・色空間の変換は発生します。余白と角丸のpx表示は出力画像基準です。倍率は1〜6倍。レイアウト変更・枚数切り替え・並び替えでも写真の位置と倍率を保持します。配置に合わせて表示位置を枠内に制限します。写真を明示的に削除・差し替えた場合のみ元写真を解放します。

対応レイアウト：2枚（上下、左右）、3枚（上1＋下2、左1＋右2、縦3分割、横3分割）、4枚（2×2、上1＋下3）、5枚（上2＋下3、上3＋下2、上1＋下4）。

ブラウザがデコードできる画像に対応します。HEIC対応はOS・ブラウザに依存します。読み込めない場合はJPEG/PNGで選び直してください。写真・編集状態は永続保存しません。リロード・終了時に消えます。大きな写真を複数選んだ場合のメモリ制限は端末に依存します。

## PWA

HTTPSで一度アクセス後、iPhone Safariの共有メニューから「ホーム画面に追加」でインストールできます。Androidはブラウザのインストールメニューを利用します。Service Workerは同一オリジンのアプリ資源のみをキャッシュします。最初のオンライン読込完了後はオフラインで使用できます。写真のblob URLはキャッシュしません。更新時はオンラインでアプリを再読み込みしてください。キャッシュには写真は残りません。

## GitHub Pagesへの公開

`.github/workflows/pages.yml` を同梱しています。

1. このコードをGitHubの `main` ブランチにpushします。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. **Actions → Deploy to GitHub Pages** を実行（mainへのpushでも実行）します。
4. deploy完了後、Pagesに表示されるURLから利用します。

Viteの `base: './'` と相対manifest/SWパスにより、`/shuppin-photo/` 配下と独自ドメインの両方に対応します。ビルド成果物は `dist/`。公開には上記ワークフローの実行が必要です。ブランチへのpushだけでは公開されません。

## 検証

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
# システムにChromiumがある環境の場合
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

単体テストは全11レイアウトの領域数・境界・重なり、余白なしの面積、拡大・移動時の画像のはみ出し制限を確認します。E2Eは320〜430px幅のChromiumで画面の収まり、空き枠からの写真選択、枚数変更時の写真保持、横スクロール、写真読込・レイアウト変更・差し替え・並び替え・編集・JPEGの寸法と形式・ダウンロード・エラー表示・オフライン再読込を確認します。

実行結果および実機チェック項目は [TESTING.md](TESTING.md) を参照してください。

## iPhone向け保存処理

すべての表示枠に写真が入っている状態で、写真・レイアウト・編集状態が変わると180ms待って保存用の2000×2000px JPEG（品質0.95）を事前生成します。準備中は保存ボタンを無効にし、完了後のタップ処理内で、`await`や画像変換を挟まずに `navigator.share({ files: [file] })` を呼びます。古い編集状態に対応する非同期生成結果は破棄します。生成に失敗した場合は編集内容を維持し、保存ボタンで生成を再試行できます。

ファイル共有非対応・権限拒否・共有キャンセル時も、完成JPEGを表示し続けます。同じFileで再共有でき、長押し保存用の画像・ダウンロード用URLは画面を閉じるか編集を変更するまで保持します。共有の成功応答は写真アプリへの保存完了とはみなしません。

共有画面の「画像を保存」の表示はiOS側が決めるため、Webアプリから表示や選択を強制できません。Safariとホーム画面PWAはHTTPSで使用してください。iPhone実機での共有画面・長押し保存・ホーム画面PWAの動作は未検証です。

## スマホ画面への対応

縦向きは `100dvh` を使い、右上の保存・中央の正方形・下部ツールを1画面に配置します。ノッチとホームインジケーターは `env(safe-area-inset-*)` で余白を確保します。レイアウト候補が収まらない場合は一覧だけが横スクロールします。横向きなど高さ540px以下では、極端に小さいキャンバスを避けるため画面全体を縦スクロールでき、上部の保存バーは追従します。

OS標準の写真選択画面を利用します。iPhone上の写真ライブラリ選択・ノッチの実際の余白・Safariのアドレスバー開閉時のリサイズは実機未確認です。
